## 1. 가장 먼저 — 계정 인수

다른 모든 것보다 이게 먼저다. 저장소가 **전임자 개인 GitHub 계정(`iambin2`) 소유**라, 계정 접근권이 없으면 후임은 사이트를 한 글자도 고칠 수 없다.

| 방법 | 어떻게 | 알아둘 점 |
|---|---|---|
| **동아리 조직 계정** (권장) | GitHub에서 무료 Organization을 만들어 동아리 소유로 두고 저장소를 옮긴다 | 회장이 바뀌면 계정이 아니라 권한만 넘기면 된다. 사이트 주소가 바뀌므로 인스타 링크 등을 갱신할 것 |
| 후임에게 소유권 이전 | 저장소 `Settings` → 맨 아래 `Transfer ownership` | 주소가 후임 아이디로 바뀐다. 매 학기 반복해야 한다 |
| 공동 관리자 추가 | 저장소 `Settings` → `Collaborators` → 후임 초대 | 주소는 유지되지만 소유권은 전임자에게 남는다. 임시 방편 |

**장기적으로는 동아리 도메인을 사는 것이 가장 깔끔하다.** 연 1~2만 원이면 계정이 몇 번 바뀌어도 사이트 주소가 영원히 유지되고, 지금까지 뿌린 모든 링크가 계속 살아 있다.

## 2. 작업 흐름

이 저장소는 **클로드 코드(Claude Code)** 로 작업하도록 정리되어 있다. 저장소 폴더에서 클로드를 실행하면 `CLAUDE.md`를 읽고 프로젝트 규칙을 알아서 파악한다.

```
1. 저장소 폴더에서 터미널을 열고  claude  실행
2. 하고 싶은 작업을 한국어로 말한다
3. 클로드가 index.html 을 고치고 검증까지 돌린다
4. 결과를 확인하고 "커밋하고 푸시해줘" 라고 말한다
5. 1~2분 뒤 사이트에 반영된다 (Ctrl+Shift+R 로 새로고침해 확인)
```

처음 한 번만 하면 되는 준비:

```bash
git clone https://github.com/iambin2/pokemon-center-yonsei.git
cd pokemon-center-yonsei
npm install          # 검증 도구(선택)
```

### 자주 하는 작업

그냥 이렇게 말하면 된다. 클로드가 규칙을 이미 알고 있다.

- `8기 임원진을 추가해줘. 명단은 [이름/직책/학과/학번/최애포켓몬] 형식으로 줄게.`
- `이 포켓몬 이미지들을 해당 임원 카드에 넣어줘.` (이미지 첨부)
- `FAQ에 "회비는 언제 내나요?" 질문을 추가하고 답변은 "매 학기 초 정모에서 안내합니다"로 해줘.`
- `회장을 홍길동, 연락처를 010-0000-0000으로 바꿔줘.`
- `연혁에 2026년 3월 8기 출범 항목을 추가해줘.`
- `배포하고 나서 사이트가 이상해. 원인 찾아서 고쳐줘.`

번역은 따로 부탁하지 않아도 된다. 세 언어를 함께 고치는 것이 프로젝트 규칙으로 등록되어 있다.

## 3. 매 학기 할 일

1. **새 기수 임원진 추가** — 명단을 받아 추가하고, 기수 수와 인원수 표시를 갱신
2. **포켓몬 이미지 넣기** — 새 임원들의 최애 포켓몬 공식 이미지를 모아 한 번에
3. **회장·연락처 갱신** — 졸업한 사람의 개인 번호가 사이트에 남지 않도록 반드시 교체
4. **회원 수와 연혁 갱신** — 가입 섹션 "가입 전에 알아 두세요" 칸과 소개 문단의 회원 수, 그 학기의 큰 일
5. **계정 인수 점검** — 회장이 바뀌었다면 1번을 다시 확인

## 4. 지켜야 할 것

- 파일 이름은 항상 `index.html`
- `og.png`를 지우지 말 것 — 카톡·인스타 링크 미리보기 이미지다
- `.github` 폴더를 건드리지 말 것 — 자동 배포 설정이다
- 작업 전에 항상 `git pull` (또는 GitHub Desktop의 `Fetch origin` → `Pull origin`)
- 배포 후에는 휴대폰에서도 한 번 확인할 것

## 5. 망가졌을 때

클로드에게 `직전 커밋으로 되돌려줘`라고 하면 된다. 직접 하려면:

**GitHub 웹에서**
1. 저장소 상단의 커밋 개수(예: `15 Commits`)를 클릭
2. 문제가 생기기 **직전** 커밋의 `<>`(Browse files) 아이콘 클릭
3. 그 시점의 `index.html`을 열고 `Download raw file`로 내려받기
4. 그 파일을 `Add file` → `Upload files`로 다시 올리기

사이트가 아예 안 열린다면 저장소 `Actions` 탭을 볼 것. 빨간 X는 배포 실패다.

## 6. 컴퓨터 없이 급하게 고쳐야 할 때

PC방 등 남의 컴퓨터에서는 **시크릿 창**(`Ctrl+Shift+N`)으로:

1. 저장소 접속 → 로그인
2. `Add file` → `Upload files`
3. 파일 드래그 → 커밋 메시지 입력 → `Commit changes`
4. **반드시 로그아웃하고 시크릿 창 닫기**

집에 돌아와 GitHub Desktop을 쓸 땐 `Fetch origin` → `Pull origin`을 먼저 눌러야 충돌이 안 난다.
